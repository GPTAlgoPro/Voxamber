# Native image model recheck — read-only recommendation

Recommend **one next candidate: FLUX.2 klein4B distilled INT4, resident512**, using the MIT `nanguoyu/flux-2-swift-mlx` library directly. This is a proposed comparison, not an App selection, download, port, compilation success, phone result or image-quality pass. The current canonical SDXL LP baseline remains a failure: it depicts a desk lamp but not the requested red conical shade; changing seeds to find a better result is not acceptance.

User limit is **each independently deployed model component ≤8B**, not an explicit cap on the sum of separate models. The earlier aggregate7.912B was our conservative design. Count total dense parameters, never MoE active parameters. Serial loading changes peak memory, not the number of model parameters installed. Apple's opaque Vision system-model parameters are unknown and excluded from these auditable self-distributed totals.

## Phone evidence boundary

The [MobileDiffuser author](https://github.com/TWWinde/MobileDiffuser/blob/0f56c18ccf545e7532c8e0231671714b471c88f0/docs/IPHONE_OOM_DEBUG.md) reports physical-device runs with increased-memory entitlement. Its linked [MemoryProbe](https://github.com/nanguoyu/swift-diffusion-core/blob/80d7b8b9415c1a0f3d4f51ec9d377b9cdddcb9f9/Sources/DiffusionCore/Memory/MemoryProbe.swift) actually reads task_vm_info.phys_footprint and os_proc_available_memory. This is stronger than a bare model-size estimate, but remains **author-reported first-party evidence**, not our iPhone validation. No raw ips/complete sampling receipt was found in the inspected tree. Exact OS/thermal/repeat/cancel bounds are not supplied. The1024 documentation mixes an MLX-peak line with device-peak wording; this recommendation uses the512 claim and still requires our actual6GiB process-budget test.

Code supports staged residency. [Flux2Pipeline](https://github.com/nanguoyu/flux-2-swift-mlx/blob/57ad4818ecaa4367616d0c046a24e4694bb07779/Sources/Flux2Core/Pipeline/Flux2Pipeline.swift) materializes text embeddings then unloads Qwen. The iOS T2I branch unloads the transformer before decode. This last unload is conditionally **iOS only**; normal Mac residency is not automatically a faithful phone-memory proxy. Four distilled steps also require cache-trim cadence1 rather than the generic default5 if recreating the reported phone profile. Author streaming/resident parity tests are same-Swift-path comparisons, not proof of official PyTorch numerical parity or LP semantic quality.

The default9B component violates the present cap, and no inspected nativeSwift phone implementation/parity path was established. It is not the smallest executable next step; Python MFLUX support is not an App-native runtime.

## Exact proposed assets and no-network admission gap

`proposed-flux2-assets.json` pins every proposed large payload by full HF revision/LFS SHA and small metadata by downloaded whole SHA. Only small metadata was fetched; **no tensor payload was downloaded**. Selected payloads:

- DiT: `mlx-community/flux2-klein-4b-4bit@860e87183ceb29e39627c0612ebd66d8ea66e68c`, transformer0/1 shards, total2,180,051,493bytes; mflux MLX affine4bit/group64 format, not BF16 loaded then quantized on phone.
- Qwen: `lmstudio-community/Qwen3-4B-MLX-4bit@480ec45ecf06ae3c061e4ef11345d05c7fdb02f1`, model2,263,022,417bytes, config4bit/group64 and local tokenizer files. This is the core's actual selected encoder repo, not its unused community sibling directory.
- VAE: `black-forest-labs/FLUX.2-small-decoder@a3efc24f613ef42d9428af62fdbd6f5fd8856c4a`, `diffusion_pytorch_model.safetensors`249,521,340bytes plusconfig. FullAE F32, not a fictitious prequantized VAE. Native loader explicitly prefers this filename; it is the direct supported route. Decoder-only111.8MB variant exists but is not substituted into this first contract.

Tensor payload total4,692,595,250bytes plus≈11.5MB tokenizer/config/index; retain the separately pinned upstream license texts and model-card attribution. Disk≠RAM. HF/API metadata identifies exact payloads; they are not locally verified until a future authorized download streams all SHA checks.

Important core API hazard: `.transformer:.int4` alone maps to a BF16 variant and quantizes on load. Future SDK must explicitly set **transformerVariantOverride:.klein4B_4bit** or risk an8GB load spike. `KleinTextEncoder.load(from:)` supports a local directory, but private pipeline load and global ModelRegistry/downloader currently auto-discover caches/auto-download. Before App use, add a strict caller-pinned local-resource seam/fail-closed no-network guard; do not read arbitrary other-app caches. Do not infer complete-install readiness from upstream's directory-exists tests.
