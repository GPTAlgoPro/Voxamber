# CPU mesh edit and real artifact export

The SDK now exposes synchronous `ShapeMeshEditor.export(base:recipe:baseArchiveData:isCancelled:)`. The caller runs it in an owned background task, cancels that task and awaits it. It returns independent buffers, real GLB/USDZ Data, Float bounds, statistics and a CPU edit receipt. It does not invoke any model, quantizer or script runtime and is not an AI-generation success.

The immutable base is never modified. Root should pass the exact original layout1 `baseArchiveData`; its decoded positions/indices must match the buffers and its SHA is bound in the receipt. A missing archive argument uses the SDK's canonical source-layout1 encoding. The recipe is always applied from that base, not repeatedly baked onto previous render versions. Store retains original neural generation evidence and parent revision; the separate edit evidence has `actualNeuralWeightsUsed:false`.

Recipe version1 stores Double translationXYZ, rotationXYZdegrees, positiveScaleXYZ and optional wholeMaterial. Positions apply S→Rx→Ry→Rz→T. Normals apply the inverse transpose and normalize. Positive scale, finite data, original valid triangles, output coordinate/extent bounds and post-Float32 noncollapse/nonreversal are checked. Values above1,000,000model units are rejected. Planar surfaces are permitted. These are normalized/model-coordinate export limits, not guaranteed metre accuracy. In particular, tiny geometry translated far away may explicitly fail Float-precision validation rather than quietly losing faces.

Render GLB remains standard glTF2 but carries indices0, POSITION1 and actual transformed NORMAL2 plus optional uniform PBR. Base layout1 remains POSITION/indices only and unchanged. Root Storage validation accepts optional render NORMAL while keeping the base strict. USDZ writes actual transformed points/normals and a bound UsdPreviewSurface with opacity, metallic and roughness. No material-only viewport shortcut is used.

The API color factors are linear Rec.709/sRGB. GLB writes those standard factors directly. Apple's native USD importer exposes constant colors as linearDisplayP3; merely putting Rec.709 numbers into that container produced a measurable color mismatch. The new USD material converts to linearP3-D65 and explicitly declares `lin_p3d65_scene`, one of OpenUSD's standard color spaces. A native importer readback, converted to linearRec.709, matches the input within1e-5; metallic, roughness and effective opacity are also checked. This conversion applies only when an edit material is present; the default generation artifacts retain their old hashes.

The synthetic154,449vertex/307,328triangle test checks every POSITION/NORMAL scalar from the actual GLB binary and USDZ USDA payload, PBR fields, native bound material, unchanged index buffer and base SHA. The original default GLB SHA58c3c024…102d7b and default USDZ SHAa7d17bb3…db376 are hardcoded regression identities. The edited GLB independently passes Khronos validation with0errors/0warnings. These are CPU geometry/file tests, not neural quality, real-user interaction or phone acceptance.

Recipe JSON fields: formatVersion, translationXYZ, rotationXYZdegrees, positiveScaleXYZ, wholeMaterial (nullable/omitted). WholeMaterial fields: rgba (four linearRec.709 Doubles), metallic, roughness. The exact edit receipt is emitted in the ignored fixture's edit-receipt.json and mirrored in this prototype's verification data. Byte counts are Int64; counts are Int; hashes lowercaseSHA256. The receipt is integrity evidence, not a signature or visual-quality certificate.

Primary color-space reference: [OpenUSD Color User's Guide](https://openusd.org/25.11/user_guides/color_user_guide.html), including per-attribute colorSpace metadata and LinearRec.709/LinearP3-D65 standard tokens.
