# Neural mesh edit records

Storage types are Foundation/CryptoKit-only, with no import of the Shape or MLX runtime. `NeuralWholeMaterial`, `NeuralEditRecipe`, and `NeuralEditEvidence` have the same serialized fields and scalar types as `ShapeWholeMaterial`, `ShapeEditRecipe`, and `ShapeEditValidationReceipt`. Their DTO JSON can round-trip the actual SDK output. `NeuralEditRecipe.sha256` uses the SDK's JSONEncoder `.sortedKeys` convention, including optional material omission, so an evidence record is bound to the exact recipe. Colors are linear Rec.709 RGBA, not display gamma values or texture claims. Scale is positive; transforms follow S→Rx→Ry→Rz→T; output bounds are model coordinates, not evidence of physical metres.

Operation input is `NeuralEditRecord(parentRevision:recipe:evidence:) throws`. `record.validate(parentRevision:)` verifies the operation's parent and receipt/recipe consistency. `NeuralPublicationInput` adds an optional `editRecord` initializer argument defaulting to nil. `NeuralProjectDescriptor` persists optional `editRecipe` and `editEvidence`; its existing initializer remains source compatible through default nil arguments. The persisted parent lives in `provenance.parentRevision`; the immutable parent revision preserves the original method and input parameters.

`descriptor.validate(requireEditRecord: true)` is required for **new publication**. The default false permits existing V2 revisions that completely lack both new fields, including the previously representable edit branch, to remain readable. Whenever either new field is present, both must be present and the complete record is validated irrespective of that default. Non-edit provenance cannot carry these fields. Restoring legacy compatibility is distinct from admitting a new edit without evidence.

An edit requires a parent revision, unchanged base SHA matching the original generation evidence, preserved topology/counts, actual rendered GLB/USDZ hashes and byte counts, exact recorded output bounds/statistics, inverse-transpose normalized normals, truthful whole-material application, and `actualNeuralWeightsUsed == false` in the edit receipt. Original `generationEvidence` remains separate and must still report neural origin for non-synthetic projects. A CPU edit receipt must never replace that original generation receipt. Records are traceable integrity metadata, not signatures, neural-origin attestations, or visual-quality scores.

## Parent-owned publication integration

Root owns `NeuralProjectValidator`, `ProjectStore`, `StudioModel`, and UI. Minimal wiring agreed for the validator is to validate `input.editRecord.parentRevision` against provenance, pass its recipe/evidence to the descriptor, and call `descriptor.validate(requireEditRecord: true)`. Existing file hashes, copy transaction, publication permit, CAS and immutable revision layout remain in force.

The Store's edit branch additionally has the actual previous project available. It must check that the parent is that current revision; original generation evidence, base statistics/base hash, source PNG hash and raw input/stage/brief provenance remain unchanged. Only edit method, parent revision and edit time describe the new operation. These cross-revision checks cannot be proven by a standalone descriptor, and are not claimed by this DTO receipt. Root performs that integration separately.

## Verification scope

Seven host Release tests use the existing real Shape SDK CPU-export fixture: 154,449 vertices, 307,328 triangles, 921,984 indices. They compare recipe/evidence JSON fields without loss, the SDK recipe SHA, actual exported artifact sizes/hashes, optional-field backward compatibility, strict new-edit admission, parent binding, independent origin vs edit flags, and malformed or altered metadata rejection. This fixture ran no neural model. Positive tests of the original-neural-origin rule use explicitly **simulated true metadata solely to exercise validation**; the actual CPU export receipt always stays false. They are not neural generations, publications, device results, or entries restored into the user's library.

For App unit tests the conditional branch generates a fresh dense fixture with the actual Shape SDK CPU editor. That branch was separately typechecked against the real Shape SDK module on Mac; execution belongs to the parent's combined App suite. The standalone host tests instead consume the already frozen same SDK CPU artifacts and do not regenerate/replay any neural output. iOS26 arm64 source typechecking covers the production descriptor/DTO with the exact production storage-error enum. Full App compilation, Store publication/CAS integration, edit UI acceptance and phone behavior require separate evidence.
