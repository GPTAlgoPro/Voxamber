# 原生结构化造型生成修复

当前发版为 TestFlight 0.1.0 (3)。继续在 dev 开发；本方案不把停止热修、JSON 通过或格式可导出视为通用造型质量通过。

## 已有证据

正式 Direct 推理、同一 Qwen3.5 4B INT4 和固定请求的五次新建中，两次得到场景，三次未通过 JSON 校验。独立诊断重现：椅子和飞行器达到 3072 token 后仍未闭合，且分别已经超过部件/轮廓点预算；鲸鱼没有达到输出上限，却出现数组内多余引号。增加 token 不能覆盖全部原因。详见生产质量及 rejection-diagnostics 回执。

## 实施选择

保留已经过手机取消和卸载验证的 TokenIterator、prefill 128、generateTokenTask、取消转发、等待 producer 和 GPU 同步。通过固定 MLXLMCommon 3.32.3 的 GenerationComponents 注入原生 LogitProcessor，以 MLXGuidedGeneration 的 GrammarConstraint 限制下一 token。每请求独立 matcher，禁用当前 Direct 无法执行的 fast-forward，处理词表 padding 和 EOS。原生回调错误采用受控错误通道，使任务失败并完成清理。

CreationCore 生成完整 ScenePlan JSON schema，覆盖全部八种几何及现有可编辑场景：32 部件、64 轮廓点、1024 顶点/2048 面的原有上限先保持。限制合法数值、基本字段和几何专属字段，保留 origin/attach 两种定位方式。题材由用户自由描述。唯一标识、引用、拓扑、网格非退化和视觉结果继续由后续原生验证与实际审阅负责。

先测完整 schema 的真实完成率、耗时和内存，再根据证据决定每次请求的复杂度分配。不能为通过固定样例而取消自由几何、预设补位、修改生成结果或缩窄为几个物体类别。输入的现有完整场景须仍可编辑，不能因收紧 schema 破坏已保存作品。

区分完整结束、输出上限、语法约束失败、普通格式拒绝和取消，记录计数及时间，不记录用户描述/生成正文。Direct 诊断仍允许返回小 token 上限的片段；正式生成拒绝不完整响应，不补括号伪造成功。

固定 SDK 的真实兼容边界：vendored XGrammar 0.1.30 没有实现 matcher fork，独立 matcher 须重新建立并在复制时重放已接受 token，不能把公开 clone 方法的存在当作可用证据。bounded 浮点语法仅支持六位小数，不能接受合法的精确 Float 快照及科学计数法；编译入口仅移除 `type:number` 的范围关键字，保留完整权威 schema、整数索引范围和结构预算。所有浮点范围仍由 ScenePlan/SceneSpec 在生成后严格验收。该兼容处理不代表语法组件保证数值或几何正确。

普通 AI 生成期间使用有归属的系统常亮租约，结束或清理后还原之前的设置；参数生成保持原行为。后台依然遵守原生推理限制并收束任务，常亮不是后台推理替代。

## 验证与交付门槛

1. CreationCore 现有测试及 schema 的有效场景/自由几何编辑覆盖。
2. 原生 grammar 的独立状态、EOS、词表 padding、错误路径及完整 schema 编译；拒绝已观察到的语法/预算错误。
3. 同一正式 API、权重和固定请求重新端到端生成，保留每次结果、真实资产和拒绝原因；实际检查几何及渲染图，独立进行文件验证。
4. 取消、卸载、重新加载与内存回收；App 常亮租约、失败/取消/清理和已有存储回归。
5. 实机性能、停止、新版 Apple 素材冷下载、离线运行及 Duo 分享等未验收项继续单独记录。设备不可连接时不能用 Mac 或模拟器代替实机结论。
6. 源码与所需原生库许可齐备，再决定新 TestFlight 包；main 仅在已验证发版后合并一次。全目标继续保持未完成状态，直至用户要求的端到端体验有相应证据。

## 实测后的架构判断

完整语法约束使椅子请求输出可解析并能导出，但首轮实物图失败：尺寸轴混淆、四腿重叠及多余假连接件。仅将编译后的字段顺序改成 required-first 的受控试验改善了尺寸方向，仍把四腿串成垂直链，且补满32个冗余部件。两轮均保留真实资产和失败审阅；不能把JSON通过当作造型成功。

下一项只在 ignored runner 中验证两阶段架构：模型先输出必要部件、几何类型、用途及连接图；原生校验图后，以该模型自己选择的部件和关系构造精确数量/标识/关系的 ScenePlan schema，再由同一模型生成几何参数。保留全部8种几何和完整原有资源预算，不硬编码椅子模板、尺寸、坐标或题材。先用同一固定请求检验结构是否改善，真实图和几何通过后才考虑接入App并扩大自由题材验证。
