# 0.1.0 (6) AI、预览与作品库修复

用户在 iPhone 上使用短描述创建扶手椅时，App 5 报“造型参数超过本次生成长度”。手机记录为 `outputLimit`：1038 输入 token、3072 输出 token、上限 3072。该记录不能证明旧输出究竟是未完成的场景、重复内容还是尾部空白；旧正文未保存。短描述不是需要用户修正的问题。

已确认：选择灵感示例后，尚未参数生成的场景因为 `assets == nil` 没有传给 AI。现在生成会捕获未发布的当前场景；未编辑空白工作区不传默认球体，跨中英文切换也保持此规则。删除当前作品时立即持久化空白草稿，防止重开恢复已删的造型上下文。

正式 AI 通道在完整输出可解析为一个 JSON 对象时停止自身生成器，并等待生成器和 GPU 收束。用户取消仍优先；不会补括号、截取嵌套对象或修复损坏的输出。原来的 3072 token 上限保持不变。错误文案不再要求用户简化短描述。

此前 App 4 的自动停止另有真机证据：普通内存警告触发了无条件取消。现在普通警告先回收空闲缓存并重查余量，危险压力才停止；签名和配置加入 increased-memory-limit。在同一台 12GB iPhone、同一可执行文件的签名对照中，测得进程限制从约 3.30GiB 增至 6GiB。这是运行时快照，不是未来所有分配都能成功的保证。

预览加载改为有生命周期归属的任务，取消不会成为永久文件错误，过期加载不能覆盖新结果。作品库从实际 USDZ 生成缩略图，缓存包含作品版本和文件校验值；缩略图失败不会撤销已保存作品。
