# 0.1.0 (3) 停止与重试热修边界

用户报告 AI 运行数秒后出现“正在停止”，且停止等待可超过100秒。诊断验收中包含首 token 后主动取消的一段；这不能使百秒等待成为正常行为。

已证实并修复的路径：
- 旧诊断任务曾不归 StudioModel.work 所有，取消状态不能约束真正运行的诊断任务；该任务归属修复已进入 build 2。
- build 3 将一次操作及其后续清理共同纳入 busy；旧任务完成不能提前开放重试，也不能清掉后来任务的状态。重复后台/内存事件合并为一次清理。
- 模型卸载立即标记 loaded=false 并阻止 prepare，所有卸载调用者等待同一任务，状态在共享任务结束前完成更新。
- 后台额度到期立即结束额度；正常清理再次结束为幂等操作。

验证：先前24项模拟器单元测试通过；最终7项停止专项测试通过，含8个并发卸载调用者返回瞬间的状态检查。详见 cancellation-cleanup-fix-validation.json。Duo折叠与旋转另有独立回执；横向分栏限制导致的竖屏预览消失已改为系统自动分栏。

真实 iPhone 的既有正式 Direct 引擎取消记录为0.0526秒，随后卸载0.0455秒（phone-build1-engine-acceptance.json）。这份旧引擎记录不等于新版 Studio UI 的停止延迟验收。当前设备不可连接，尚未复现用户原始的百秒等待，也不能由上述竞态单独证明其唯一根因。

Swift取消仍需原生模型载入、tokenizer、生成producer和GPU同步返回。不能靠提前显示空闲来宣称模型已停止。新版实际停止/再次生成、Apple素材冷下载及离线运行仍须TestFlight实机验证。

通用造型质量单独追踪于 ../2026-11-05-production-quality/README.md；停止热修和文件可导出不代表自由建模质量已达标。
