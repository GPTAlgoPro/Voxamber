# Isolated sampling comparison — preparation only

No model generation has started. The candidate package and runner live only in ignored `Apple/.build/SamplingCandidatePackages/QwenNative` and `Apple/.build/sampling-fresh-five-runner`. Production App/package sources are unchanged. CreationCore and ThreeLiveNative are referenced from their current production paths read-only; model weights are referenced in place and never copied or downloaded.

The control is the completed [App 6 greedy fresh-five baseline](../2026-11-06-app6-fresh-fivecase/README.md), not the old three-stage experiment. The hypothesis is narrow: the published general non-thinking sampling settings may reduce repetitive expansion, which **does not imply overall instruction, geometry or visual quality improves**.

The only inference difference is temperature 0.7, top-p 0.8, top-k 20, min-p 0, presence penalty 1.5, identity repetition penalty 1.0 implemented by no repetition processor, and fixed per-request seed `0x5EED` (24301). The pinned native SDK supports a per-sampler `GenerateParameters.seed`, avoiding a global RNG mutation.

Independent source review found that the SDK's default presence window is 20 and includes prompt tokens. This candidate deliberately uses **generated-only presence over 3072 tokens**: a fresh `PresencePenaltyContext(1.5,3072)` wrapped with a no-op `prompt(_:)`, forwarding `process` and `didSample`, installed through a per-generation `GenerationComponents` factory. `GenerateParameters.presencePenalty` is nil to prevent applying the penalty twice. A 3072-token window covers all generated history within the unchanged 3072 output cap; zero is not used as an alleged unlimited window. This is the declared native interpretation, not a claim of complete vLLM numerical equivalence. The pinned SDK applies top-p → min-p → top-k before temperature scaling, which can differ from another backend's ordering. No run is allowed until Root gives GO.

Everything else remains the current protocol: same Qwen3.5 4B INT4 bits, current ScenePrompt, no preset/current scene, no JSON schema constraint, max output 3072, prefill 128, maximum KV 8192, early JSON stop, native cancellation/await/synchronization/lifecycle, and byte-identical production formal JSON validation after preserving same-call raw. There are no prompt edits, category-specific assembly rules, fallback parameters, retries or output repairs.

The future authorized batch will contain exactly one model load and five sequential, fresh calls in robot/lamp/whale/aircraft/chair order. All five fixed requests and the full predeclared visual/dimension rubric are copied by reference from the control protocol and must remain byte-identical. A call that has started is never replayed after failure. The same 180-second case/generation deadline and honest synchronous-render limitation apply. Rejected raw and terminal metadata remain observable from that same call.

Valid scenes alone may enter unchanged native geometry, GLB/USDZ export and two actual Apple renders; individual image review and explicit instruction/geometry requirements remain necessary. A reduction in token count, valid JSON, or nonempty files is not a visual-quality pass. Root reviews images. No phone, model switch, TestFlight or account operation is part of this experiment.

This is a nonrandom, sequential comparison with one fixed seed and one attempt per subject, not a statistically reliable estimate of success rate. It cannot establish seed robustness, iPhone latency/memory, all-topic generalization or production readiness. All control artifacts remain frozen.
